### 三. 当前完整技术架构说明

#### 1. Retrieval Planner

`planning/retrieval_planner.py` 使用 DeepSeek Function Calling，把用户问题拆为
一个或多个语义任务。每个任务包含：

```json
{
  "query": "安徽省网络安全采购项目",
  "categories": ["tender", "policy"],
  "subcategory_hints": {},
  "metadata_filters": {
    "tender": [
      {
        "field": "province",
        "operator": "eq",
        "value": "安徽省"
      }
    ]
  },
  "top_k_per_category": 8
}
```

完整计划还包含：

```text
requires_web_search：是否明确要求联网或指定网站
requires_fresh_data：是否要求最新、近期或新闻
answer_focus：答案需要重点覆盖的内容
planner_source：LLM Function Calling 或规则降级
planner_warning：Planner 降级原因
```

Planner 不允许生成 SQL，也不允许直接输出 Milvus filter 字符串。DeepSeek
调用失败时，使用本地关键词、URL、地区和统一社会信用代码规则生成基础计划。

#### 2. 六分类路由

```text
enterprise：企业、工商、供应商主体、法人、资质、信用代码
tender：招标、采购、中标、成交、项目公告、评标
product：产品、设备、软件、材料、型号、供应商、报价、价格
laws：法律、行政法规、司法解释、责任、处罚
policy：部门规章、规范性文件、地方政策、通知、办法
news：最新消息、近期动态、新闻；当前只联网
```

多意图问题可以同时检索多个分类。例如“某企业近年的中标项目及适用政策”可以
同时选择 `enterprise`、`tender` 和 `policy`，不会强制只保留一个分类。

#### 3. 五类物理隔离的 Milvus Lite 数据库

```text
milvus_db/
├── enterprise/main.db
├── tender/main.db
├── product/main.db
├── laws/main.db
└── policy/main.db
```

每个分类使用独立数据库，避免不同内容类型的原始 COSINE 或 BM25 分数被直接
混合比较。每个库的 Collection 名称为 `records`，主要字段为：

```text
id
category
subcategory
source_id
title
content
source
metadata
updated_at
searchable_text
dense_vector
sparse_vector
```

其中 `sparse_vector` 由 Milvus BM25 Function 根据 `searchable_text` 自动生成。

#### 4. 大分类下的子分类数据库

当某个大分类需要进一步拆分时，数据库保存为：

```text
milvus_db/<category>/subcategories/<subcategory_hash>.db
```

例如产品可以使用 CSV 的 `major_category` 字段拆库。Planner 明确给出子分类
提示时只打开对应子库；没有子分类提示时，检索该大分类已有主库和所有子库。

#### 5. Milvus 元数据过滤

本地 `retrieval/metadata_filter.py` 只允许：

```text
eq   等于
in   属于非空列表
gte  大于或等于
lte  小于或等于
```

主要白名单字段：

```text
enterprise：
enterprise_name, uscc, corporation, province, city, district,
industry, enterprise_type, status, event_time,
registered_capital_amount, subcategory, source

tender：
tender_title, project_type, source_name, province, city, town,
purchasing_staff, bid_company, event_time, bid_date, bid_amount,
subcategory, source

product：
title, major_category, middle_category, supplier_name, currency,
province, city, event_time, amount, subcategory, source

laws / policy：
title, subcategory, source, updated_at
```

`registered_capital_amount`、`bid_amount`、`amount` 按数值处理。字符串使用 JSON
规则转义，不能通过过滤值插入额外表达式。无效字段会产生 warning，并跳过该
分类任务，不会不受限制地执行模型输出。

#### 6. Dense + BM25 双路召回

同一分类、同一分片、同一元数据过滤表达式下分别执行：

```text
Dense：
BAAI/bge-base-zh-v1.5
COSINE
适合同义表达和描述性需求

BM25：
Milvus BM25 Function
jieba 中文 analyzer
适合完整名称、代码、编号、型号和关键词
```

Dense 按分类阈值过滤：

```text
enterprise = 0.68
tender     = 0.65
product    = 0.66
laws       = 0.62
policy     = 0.62
```

每路先召回 `top_k × HYBRID_RECALL_MULTIPLIER`，默认扩大 4 倍，最大不超过
200 条，然后进入融合。

#### 7. RRF 融合与去重

Dense COSINE 与 BM25 原始分数不直接相加。系统保留两路排名并计算：

```text
RRF_score(document) = Σ 1 / (k + rank)
```

默认 `k=60`。排序分三步：

```text
第一步：单个分类分片内部融合 Dense 和 BM25
第二步：合并多个语义任务、分类和子分类分片
第三步：按 category + source_id 去重后送入 Reranker
```

#### 8. DeepSeek Reranker

Reranker 对有限候选统一判断相关性，并重点核对名称、代码、金额和日期：

```text
RERANK_CANDIDATE_LIMIT = 30
FINAL_CANDIDATE_LIMIT = 20
RERANK_MODE = llm
```

DeepSeek Reranker 调用失败时：

```text
保留当前 RRF 顺序
在 warnings 中记录失败原因
继续判断是否需要联网
```

该降级仅保证候选顺序可继续使用，不代表 DeepSeek Planner 和最终答案生成可以
离线运行。当前没有本地 CrossEncoder。

#### 9. Tavily 联网触发条件

满足任一条件时执行联网搜索：

```text
1. 用户明确要求联网搜索
2. 用户给出 URL 或指定网站
3. 问题要求最新、近期或当前信息
4. 检索任务包含 news
5. 五类本地向量库没有有效候选
6. Reranker 最高相关性低于 RERANK_WEB_THRESHOLD
```

用户指定域名时，该域名会覆盖默认政府网站范围，并对 Tavily 返回 URL 再做一次
域名过滤。例如指定 `b2b.baidu.com` 时，只保留该域名及其子域名结果。

#### 10. 上下文与答案生成

`generation/context_builder.py` 按以下顺序整理证据：

```text
enterprise
tender
product
laws
policy
news
web
```

每条证据分配 `[E1]`、`[E2]` 编号，同时保留分类、标题、来源文件、子分类、
更新时间或 URL。`generation/answer_generator.py` 要求：

```text
只使用当前上下文中的事实
重要结论标注证据编号
不把向量分数或重排分数当作业务事实
冲突时明确列出冲突
证据不足时直接说明无法确认
```

#### 11. 检索诊断

使用 `--show-plan` 输出：

```text
mysql_query_count               固定为 0
vector_hit_count                本地向量总命中数
dense_hit_count                 Dense 命中记录数
bm25_hit_count                  BM25 命中记录数
metadata_filtered_task_count    使用元数据过滤的任务数
vector_hits_by_category         各分类命中数
web_result_count                联网结果数
web_decision_reason             联网判断原因
```

元数据安全模块：

```text
维护每个分类的字段白名单

使用 JSON 规则转义字符串
编译 Milvus 标量 / JSON 过滤表达式
```

五分类混合检索模块：

```text
按分类和子分类定位数据库
```

Tavily 联网模块：

```text
识别用户给出的 URL 和域名
显式域名覆盖默认站点范围

再次验证返回结果所属域名
统一输出标题、URL、摘要和日期
```

检索总调度模块：

```text
执行全部语义任务
归一化本地候选
执行跨任务 RRF
调用 DeepSeek Reranker

合并联网结果并再次融合、重排
汇总 diagnostics 和 warnings
```

#### ranking/result_fusion.py

融合模块：

```text
把向量结果转换为 Candidate

按 category + source_id 去重
保留各召回路线和名次
```

#### ranking/reranker.py

重排模块：

```text
将有限候选提交给 DeepSeek

失败时原样保留 RRF 顺序
```

#### generation/context_builder.py

#### 当前数据责任边界

```text
Milvus Lite：
负责五类本地内容的语义、关键词和结构化条件召回

CSV metadata / content：
保存企业、项目和产品的完整非空字段，作为回答业务事实的依据

Tavily：
负责新闻、最新信息、指定域名和本地证据不足时的联网补充

DeepSeek Reranker：
负责相关性排序，不是事实数据库

DeepSeek Answer Model：
负责根据证据组织答案，不允许补写证据外事实
```

当前没有 MySQL 权威回查层。金额、日期、代码等精确条件能否正确过滤，取决于
CSV 字段是否规范、单位是否一致以及建库时是否成功转成对应元数据类型。

### 八. 推荐运行命令

激活环境并进入项目：

```powershell
conda activate cpu_default
cd D:\AI\Pythoncode\ifly_practice\bidding_agent_02
```

安装依赖：

```powershell
python -m pip install -r requirements.txt
```

创建本地配置：

```powershell
Copy-Item .env.example .env
```

在 `.env` 中至少填写：

```text
DEEPSEEK_API_KEY=
TAVILY_API_KEY=
```

准备业务和知识数据：

```text
data/csv/enterprise.csv
data/csv/tender.csv
data/csv/product.csv
data/laws/*.txt
data/policy/*.txt
```

三个 CSV 必须包含非空 `id` 字段。

首次构建五类向量数据库：

```powershell
python -m builders.build_vectors --categories enterprise tender product laws policy
```

只有确认要覆盖已经存在的新分类数据库时才运行：

```powershell
python -m builders.build_vectors --categories enterprise tender product laws policy --rebuild
```

产品按一级分类建立子分类库：

```powershell
python -m builders.build_vectors --categories product --subcategory-field product=major_category --rebuild
```

运行单元测试：

```powershell
python -m unittest discover -s tests -v
```

运行问答系统：

```powershell
python main.py
```

显示检索计划、统计和降级提示：

```powershell
python main.py --show-plan "查询安徽省网络安全项目和相关政策"
```

测试指定网站联网搜索：

```powershell
python main.py --show-plan "给我包子机的价格，基于 https://b2b.baidu.com 联网搜索"
```

如果只测试联网搜索，可以在配置 DeepSeek 和 Tavily 后直接运行 `main.py`；如果
需要 enterprise、tender、product、laws、policy 五类本地召回，必须先准备
数据并执行建库命令。
